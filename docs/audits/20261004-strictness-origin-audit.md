# 採用条件が過剰になった経路の点検

## 日付条件の実態と経緯

全情報に適用開始日を必須入力させるコードではなかった。validate_matrixがapplicable_atの非空を要求するのはhistoricalの場合。primary/corroboratedでは適用日の明記がないだけで機械的に拒否しない。
しかしモデル向け共通指示は、第三者2本文について「対象・プラン・性別・期間・機能条件・適用時点で一致」を要求していた。保存済み2026-10-04のresearch_matrixではq50/q51に「共通の適用時点が未確認」を理由とする全体不合格が実際に記録されている。したがって機械的な必須欄ではなくても、採用条件として実害があった。

Git履歴では9abde46の共通根拠方針の導入時点でこの条件が存在。c47d2fdでは公式ページについて適用開始日不要の例外を追加したが、第三者本文の条件は維持された。85e02daで第三者本文についても適用開始日不要へ修正したが、調査計画・引継ぎ・鮮度指示には古い表現が残っていた。

ユーザーの「過去情報でもいつ時点かを示して使える」「第三者の複数一致を認める」という要件から、全ての商業情報で適用時点の一致証明を求める必要はなかった。要件の厳しすぎる実装上の展開であり、ユーザーが明示した追加条件ではない。

## 今回の点検と処置

| 条件 | 判定・処置 |
|---|---|
| 一般比較にも「確実な適用時点」を求める計画指示 | 削除。掲載情報・確認日と、明示された改定日/統計期間を区別する記述へ変更 |
| 計画確認の適用日不要ルールが公式だけを対象 | 共通基準に合格する第三者情報にも揃えた |
| 全回答の引継ぎラベルが「適用時点」 | 「根拠の時点・条件」へ変更。applicable_atは保存互換性のため維持し、開始日の必須欄ではないと指示 |
| 変動情報の公式再確認が常に成功必須と読める | 関連公式の合理的な確認と、取得不能時の第三者代替へ統一。項目ごとの追加検索を義務化しない |
| 更新性の高い各記述にYYYY年MM月時点を要求 | 確認日・出典を記録し、記事注記は必要な比較表/章へまとめる。個別反復を義務化しない |
| AIがessentialにした質問の降格をコードが禁止 | 未修正。ユーザー指定の必須とAI生成の重要度を同じ扱いで固定している。検索意図に不要なAI由来義務を訂正できるか、計画の再判定との責任分担を次に整理する |
| 価格の実際の不一致、転載を独立2件と数えること | 過剰条件ではない。誤った比較を避けるため維持 |
| 過去統計の対象期間、期間限定料金の適用条件 | 通常の掲載情報の公開/確認日とは別物として維持。存在しない開始日を調べる要求に広げない |

この点検は、画像読取りの追加や補助情報の全取得を提案するものではない。取得失敗を根拠なしで合格に変更していない。

## 検証と限界

ネットワーク禁止375テスト合格。通常の第三者掲載情報は適用日が空でも採用できること、過去情報では時期が必要なこと、引継ぎが開始日を要求するラベルに戻らないことを確認。実モデルテストは今回は実行していない。API費用0円。本番・保存記事・判定・予算台帳は未変更。

全ての過剰条件を解消済みとはしない。次に残る計画固定の問題を整理し、必要な回答とAIが増やした補助条件を分ける。有料の全体再実行はその前に行わない。
