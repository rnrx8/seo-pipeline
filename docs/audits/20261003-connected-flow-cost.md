# 2026-10-03 接続後の確認工程の費用評価

## 結論

**現状の入力設計では、品質確認300円以内を見込んで有料の完了テストを再開できない。**
今回は追加API費用0円。モデル変更・合格基準変更・本番反映・予算引上げは行っていない。

対象は生成費用を除く確認工程。保存資料と過去記事の分量を使い、現在の実装が作る要求をローカルで計測したシナリオであり、実請求・新しい完成記事・完成率の測定ではない。

| 工程 | 入力20%余裕＋設定された出力枠を使う試算 |
|---|---:|
| 調査の一次判定・再読・独立確認・全体網羅性 | 約203円。資料追加を要求するシナリオでは約440円 |
| 構成の品質確認 | 約331円 |
| 完成記事の5担当による確認 | 約485円 |
| 上記の計 | **約1,018〜1,255円** |
| 本文修正1回と5担当の再確認を追加した計 | **約1,831〜2,068円** |

出力上限、余裕分、長い入力への安全側単価を使っているため、期待される実請求額そのものではない。
修正後の再確認も同程度の本文量として計算しており、修正後の記事を実際に生成して測った値ではない。
ただし、余裕分と出力を除いても、構成確認＋完成記事確認の**入力分だけで約348円**となる分量。再開時の応答再利用だけでは、新しい記事1本の費用を解決できない。
金額はリポジトリの既存の安全側単価、200円/USD、ローカルo200k計測に基づく。最新価格や為替を確認した主張ではない。
追加調査・第2回調査確認・構成修正・修正JSONの再提出・計測対象外の計画確認等は別で、これは全失敗経路を含む保証上限でもない。

## 高くなる箇所

1. 構成確認と完成記事の事実照合は各約26万ローカル入力トークン。取得原文だけで約14万、調査台帳や計画も重ねて渡している。
2. 再配分で抜粋の欠落を減らした変更は、資料量を増やす。品質面の予防と引き換えに費用が増え、今回の20%余裕込み計算では長い入力の単価区分へ入る。実際のモデル入力がその区分へ入ったことを確認したわけではない。
3. 重要論点の網羅性担当にも、大量の引用原文入りの調査台帳を渡している。事実照合担当との入力の重複が残っている。
4. 文章・全体整合性・情報整理の3担当はそれぞれ約23円。この3担当を無理に統合することが主要な解決策ではない。

同じ要求内容のままモデル名だけを変える価格比較も実施した。
- 完成記事の事実担当だけLunaと仮定：約702円。
- さらに構成確認もLunaと仮定：約388円。

これは価格計算のみで、両担当の品質・適性を検証したものではない。構成確認をそのままLunaに替える実装はしていない。安いモデルへの変更だけで解決するという根拠にもならない。

## 計測の整合性

- 保存された12件の一次判定要求は、当時の抜粋規則で再構築し、保存ハッシュと完全一致を確認してから出典IDを復元した。
- 再読と独立確認は接続した実関数を使用。ダミー応答は未確認に固定し、資料追加なし／追加ありの要求量を計測した。ダミーで未確認になった件数を、実モデルの失敗件数とは扱わない。
- 再読が成功して新たなSol確認が必要になる分は未計測。資料追加シナリオをすべての結果の最大費用とは呼ばない。
- 古いresearch_matrix_1は109項目で、現在の計画102項目とは不一致だった。これを後工程の台帳としてそのまま使わず、完全一致した保存済み判定から現在の質問ID集合に揃えた。最終計算は102項目で統一。
- 本文は過去の13,408字の記事を分量の見本として使用。今回の新フローで生成した記事でも、現在の調査台帳に対して合格した記事でもない。
- 構成確認・完成記事の5担当・本文修正は、現行の要求生成処理を通して捕捉した。前回の仮の修正プロンプトによる試算を置き換えた。
- ネットワークと生成関数を禁止し、通常の保存処理も差し替えた。既存のジョブ・記事・費用台帳は変更していない。

途中報告の重い2工程「約678円」は、項目集合を揃える前の仮計算。最終値では合計約664円。

## 次の修正対象

品質項目を減らすことや予算を上げることではなく、担当別の入力を整理する。

1. 構成・網羅性へは、質問ID、重要度、回答、適用条件、未確認・省略状態を中心に渡す。大量の引用本文は事実照合側で扱う。
2. 完成記事の事実照合は、記事の主張と該当根拠を低コストモデルで照合し、矛盾・複雑な比較・不明点をSolへ渡す。条件や隣接文を落として安くしない。
3. 修正担当へ渡す根拠も、失敗項目の担当範囲に合わせる。記事全体の整合性確認と修正後の検査は維持する。
4. まず保存データで、必要な質問・条件・引用の保持と費用を再計測する。実モデルの品質確認は別途必要。

上記は今回の実装変更ではなく、今回の積算で優先順位を確定した残作業。
