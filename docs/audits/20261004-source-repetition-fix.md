# 2026-10-04 調査から執筆までの原資料重複送信の修正

## 結果

テストブランチで、構成・紹介位置決定・本文生成・本文内の構造修正を採用済み調査から作る専用入力へ接続した。ネットワーク禁止360テスト合格。追加API費用0円、本番未変更、記事未完成。
前回の対応は確認工程の一部だけで、生成工程に原資料・ファクトシート・調査台帳を重ねて送る箇所が残っていた。今回の修正はその未対応箇所を含む。

## 変更

- 構成と紹介位置決定は、全質問・採用回答・省略状態・条件・時点・現在の結論に使えるか・出典を一つの入力へ集約。原文本文と引用全文は再送しない。
- 執筆と構造修正は、上記に採用された根拠引用を加える。完全一致する根拠は一度だけ辞書へ置き、各回答から参照する。取得原資料一式と生の調査台帳は再送しない。
- 執筆用入力を作る前に `require_matrix` で調査の合格と資料・事実・計画・方針の一致を検査。未確認や古い合格記録で執筆へ進めない。
- モデル要約や類似文字列による資料削除ではない。回答・条件・未知の追加条件フィールドはそのまま投影。省略判断と出典URLも保持。
- 最終・構成確認は、採用回答のハッシュと一致する場合だけ、ファクトシートと調査判断の回答を二重掲載しない。追加の事実確認結果など一致しない事実は残す。原文引用注記の重複だけを落とし、回答本文と出典URLは維持。
- 以前保持した未採用候補の引用が、別の確認担当へ再流入する経路を削除。調査担当の候補記録自体は保持。
- 調査の独立照合には担当外の全質問文を毎回渡さず、対象範囲と他質問IDだけを渡す。全質問は全体網羅性担当に引き続き渡す。

有効条件は従来の `ARTICLE_REVIEW_PROVIDER=tiered` と `QUALITY_RESEARCH_ROUTING=focused`。旧経路の構成・生成資料形式は維持する。
