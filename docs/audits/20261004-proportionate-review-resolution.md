# 確認結果の扱いを構成・本文・修正で統一

## 対象と原因

今回だけのサービス名や料金による特例は設けない。問題は、確認済みの条件を補えば直る指摘、要約だけでは分からない主張、担当へ資料が未提示の状態を同じfailとして原文照合・修正へ流していたこと。補助情報の省略と「情報を確認できない」という断定も区別が弱かった。

## 既存工程内の変更

共通の採用基準を置くevidence_policyに、編集時の確認結果の処理基準REVIEW_RESOLUTION_POLICYを定義。構成監査・完成本文監査・両者の局所修正から共用する。調査の採用要件そのものは変えず、調査済み回答を無効化しない。編集監査の版を更新し、古い監査合格の再利用は許可しない。

- 誤った条件・記述は軽微でも未修正のまま合格にしない。ただし修正内容が既存回答から明らかな場合、局所修正へ送る。
- 要約の短さを根拠不足と断定しない。同一プラン・対象・時点の機能表、料金表、FAQを組み合わせた裏付けを許可。別条件への推測は禁止。
- optionalな掲載項目の省略自体は不合格にしない。未確認・不存在という説明が誤りなら、その説明の削除・限定で解決可能。掲載範囲の拡大を必須にしない。
- 主要回答・比較結論に必要な条件、実際の料金誤りや文章の意味破綻は引き続き不合格。

構成監査は既存checkにrequires_source_checkを付け、既知の誤りと原文確認が必要な不確実さを分ける。既知の誤りだけなら原文照合を呼ばない。旧形式に項目がない場合は安全側の従来照合へ送る。不正な型やpassに追加確認を指定する結果は受け付けない。

原文照合ではfailだけを理由にLunaからSolへ上げる条件を削除。未解決事項、比較断定、既存のサンプル確認は維持する。局所修正で済むものはfailのまま修正へ送る。全資料を渡しても照合未完了ならevidence_pendingを残し、構成・本文とも資料不足を内容誤りとして自動で書き換えない。

部分照合で無関係な合格項目まで一括failに変える処理を除去し、未完了は根拠照合に記録する。別項目の既知の不合格を部分照合のpassで消さない。判定基準を緩めることではなく、必要な処理へ分岐させる変更。

構成の修正入力には採用済み引用も含める。短縮された回答だけに従って正しい主張を消すことを避ける。引用追加により修正1回の入力量は増える可能性があり、総費用削減の実測はまだない。全資料再読を単純にゼロにするものでもない。

新しいモデル呼び出し工程、再試行回数、ネットワーク調査、フロント変更は追加していない。

## 検証

外部接続を禁止した405テスト合格。既知の条件漏れは局所修正へ進み未修正で合格しない、原文不足だけなら本文を書き換えない、根拠照合で別の不合格を消さない、不確実な根拠を合格化しない、不正な追加照合指定を拒否することを検証。これは制御の回帰検証であり、モデルの意味理解を実測したものではない。

保存済み102項目のrequire_matrix通過。引用を含む修正入力に元の条件が残り、原文照合へ渡すconfirmed_factsは既存回答への80文字の参照となることを実データ・ネットワーク禁止で検証。保存済み記事・構成・調査台帳を書き換えていない。

追加API費用0円。有料再確認、本文生成、本番反映は未実施。次は同じ保存済み資料で局所修正と再確認を行い、判断が妥当か・余分な呼び出しが減るかを確認する。追加の有料実行には別途承認が必要。
