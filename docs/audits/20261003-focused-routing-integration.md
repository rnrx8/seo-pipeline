# 2026-10-03 保存済み資料の再確認をテスト用生成フローへ接続

追記：[接続後の費用評価](20261003-connected-flow-cost.md) で、生成を除く確認工程にも大きな入力重複が残り、現状のまま300円以内を見込めないことを確認。

## 到達点

別ブランチ `codex/quality-flow-simplification` 上で実装済み。ネットワークを禁止した326テストが合格。
実モデルの生成・新規検索・本番反映は実施していない。今回の追加API費用は0円。
既存のテスト台帳は22要求、累計$1.09825375のまま。ジョブID・予算上限を変更せず、新しい台帳も作っていない。
新フローでの完成記事は依然として未生成。

## 実装した処理

`ARTICLE_REVIEW_PROVIDER=tiered` に加えて `QUALITY_RESEARCH_ROUTING=focused` を指定した場合だけ、調査の新経路を使用する。設定ファイルや実行環境では有効化していない。

1. 従来の一次判定と全質問IDを維持する。
2. 同一要求で既に購入済みのSol判定がある場合は再利用する。
3. 非必須の省略は既存の承認済み条件でのみ候補化する。記事全体の網羅性確認は省略しない。
4. それ以外の未確認項目は、記録された公式確認先・引用先を優先し、保存済み本文をLunaで再読する。資料不足という説明自体を事実とみなさない。
5. 第三者本文等の別資料が必要なら、保存済み対象資料を一度だけ追加提示できる。公式が取れない場合の複数媒体一致・過去時点・専門家という既存の採用条件を維持する。
6. 複雑な根拠や抜き取り確認はSolが原文を独立確認する。引用先と確認済みURLの本文を優先し、必要時だけ保存済み対象資料へ一度拡張する。
7. なお未確認の必須情報は不合格のまま残す。全体の網羅性確認も従来どおり実行する。

新しい関数自身は外部検索を行わない。外側の既存の追加調査上限・予算管理は維持する。
本文提示は既存の文字数枠内のため、長い保存本文には抜粋があり得る。`sources_complete` は対象の保存ページ集合を提示した意味であり、本文全文・ウェブ全体の確認を意味しない。抜粋状態は各ページに残す。
再読で新たに見えた根拠をSolに渡す際、以前の抜粋の隣接条件も消さずに保持する。

## 再開時の重複支出を防ぐ修正

構成段階の品質確認と完成記事の修正要求にも、完全一致した要求・応答の再利用を接続した（tieredのみ）。
元本文・根拠・指示・モデル・応答形式が変われば再利用しない。
修正応答の保存後、記事への適用前に停止するケースをテストした。再開時の生成要求は一度のまま、修正記事の再検査は省略しない。
構成確認の保存済み応答も、コードによる安全保証・比較条件などの検査は再実行する。

## 後工程の受け渡し確認

- 調査合格時、採用した回答と引用から共通のfact_sheetを作成する。
- 構成・執筆はrequire_matrixで調査の合格・資料版を確認し、共通事実と取得原文を受け取る。
- 完成記事の5担当は維持する。文章・全体整合性・情報整理を統合しない。
- 最後の完了判定はAPIを呼ばず、現在の本文・出典・条件に一致する検査結果を確認する。

このため、後工程へ渡す事実が別々に再生成されているわけではない。一方、調査matrix・事実シート・原文の意味的重複はまだある。今回それを機械的に削って品質を保証したことにはしていない。

## 検証の限界と次の判断

自動テストは経路・引用ID・再開・予算停止を検査するもので、実モデルの読解精度や完成記事品質を証明しない。
前回の約58円はオフラインで組み立てた初回入力シナリオの試算。この実装は対象ごとに実行し、必要時の追加提示もあるため、その金額を実測・保証として流用できない。
再読・追加提示の出力枠が実データに十分かも実モデルでは未検証。

残る確認は、新経路の実データ入力量（通常経路と追加提示経路の両方）と、構成・完成記事検査・修正を合わせた費用の積算。その後に実モデルの限定検証で、解決率と記事完成までを確認する必要がある。
記事全体300円以内・正常な完成記事・フロント表示・本番反映は未達。上限を引き上げて達成扱いにはしていない。
