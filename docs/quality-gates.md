## 工程

検索意図 → 調査計画（質問・比較対象・選定理由）→ 初回調査 → 質問別の根拠照合 → 構成 → 構成を根拠で書けるか確認 → 執筆 → CTA → 5系統の独立確認 → 指摘統合・局所修正 → 再確認 → 最終保存判定。

完成本文の確認は evidence / coverage / language / consistency / organization の5回。各回は同じ本文を読み、書き換えない。各回の応答は個別artifactに保存する。合格判定は本文・出典・構成・設定・検査方針の指紋に紐付く。修正後は全系統を再実行し、旧本文の合格を流用しない。

文章の連続はH2/H3/H4を対象に機械検査する。空行・太字・HTML装飾はリセットしない。既存H2/H3を維持し、H3内の整理用H4追加を許可する。既存のセクションIDとCTA配置を保持する。

## 調査

必須質問は構成より先に固定する。質問ごとの回答に直接取得本文の引用を要求し、URLと原文の一致もコードで確認する。状態は確認済み・公式に非公開・未調査・取得失敗・探索したが見つからないを区別する。必須質問は最初の2状態以外では合格にしない。意味・複数社の充足はAI判定のため、引用の機械照合だけで意味が保証されたとは扱わない。

初回充足確認の追加調査は最大2回。構成後の確認でも不足があれば調査に戻り、再度質問別照合を必須にする。前回の確認済み資料を同じ実行内で保持し、不足部分だけを優先して調査する。必要論点の削除で合格にはしない。

## 表示確認

意味・情報整理と実際の表示は別。フロントのローカル専用プレビューで、実際の記事画面と同じMarkdown部品を使いPC/スマホの表示を検証する。この画面は本番では404。ブラウザ確認は今回の受入テストであり、バックエンドのAI判定が画面も確認したと主張しない。

## 検索意図と採用根拠の共通基準（2026-10-02追加）

`evidence_policy.py`を調査・構成・執筆・修正・最終監査・強化ファクトチェックで共有する。
計画は対象ごとの質問に分割し、essential / important / supporting、理由、原典必須か、現在の根拠が不可欠かを固定する。調査後の降格は禁止。
商業情報は公式を探索後、同じ対象・条件・時点を裏付ける独立した第三者本文2件以上も採用可能。転載の重複、存在しない探索URL、引用不一致は不合格。専門的判断は別基準を維持する。
過去情報は適用時点と現在の結論に使えるかを保存。補助/重要情報の省略は探索記録・理由・記事全体の網羅性判定が必要。必須回答の省略や非公表による自動合格は不可。
