# 構成設計の見直し・実装範囲

ブランチ: codex/outline-intent-design。情報処理・事実採用基準は今回の見直し対象外。

## 内容が決まる流れ

1. 検索意図・競合の重要論点・ユーザー指定から、調査計画が質問とessential/important/supportingを決める。
2. 既存の調査計画確認が過剰な必須化・主要論点の欠落・回答範囲を確認する。
3. 調査充足確認が回答・条件・採用/省略を確定する。今回この部分を追加調査・再評価しない。
4. 構成が確認済みの質問を章へ割り当てる。「セクション内容」という抽象的な欄を、読者の疑問・対応質問ID・具体的な回答要素へ置き換えた。表/リストの設計・出典対応は保持する。推薦する章以外に選ぶ価値の説明を一律要求しない。
5. 内容と子節を決めてから章の必要分量を見積もる。競合値は参考規模で、ユーザー指定とは別に構成メタデータへ保存する。参考値へ合計を合わせる機械的な再配分は行わない。
6. 既存の構成確認のcoverageが、重要論点・具体的な回答要素・概要と詳細の役割・独立章の必要性・見出し・分量の整合性を評価する。必須IDの未割当てや設計欄の欠落は課金前の検査でも検出する。IDだけ存在して内容不足でも意味の確認を通過したことにはしない。
7. 構成側のcoverage修正では、指摘対象の章構造も直せるようにした。必須回答と構造契約を保持し、修正後は既存の再確認を必ず通す。本文の局所修正で構成の不備を取り繕わない。
8. 本文は確定した回答要素と見出しを引き継ぐ。パートの推定文字数への不足だけでは再生成しない。ユーザーが明示した記事全体の分量条件は維持する。

## 2026-10-09: 読者の理解・判断の進行設計の棚卸し

ユーザー指摘: 検索意図は掘れていても、情報をどういう順に渡し、理解/不安/判断を変え、記事目的へ導くかの構成が不足。事実から場当たり的に見出しを作るように見える。本文への適用も懸念。

### 現状の確認

- 共通章設計/説明の深さは全クエリ対象。特定リスクや特定商材の禁止/必須語を追加した修正ではない。
- 通常step_outlineは検索意図、intent chains、記事目的、調査採用回答、調査優先度の理由を受け取る。確認済み情報の有無だけで掲載を決めず、主回答/根拠/背景の役割と順序へ反映する指示はある。
- 出力の基本設計欄は読者の疑問/回答要素/対応論点/表現形式/根拠であり、理解済み→その章の追加理解→残る疑問→次の判断を一連の章設計として明示させる仕組みは十分でない。
- evaluations/reader-state/prepare.pyは読者状態4項目を手動で既存部分構成へ書いた実験。READMEは通常構成の自動生成への一般化を証明しないと明記。これを通常生成の実装済み機能と扱わない。
- 本文は構成と検索意図/chainを受け、各H3の回答要素と形式に沿って書く。入力に存在することと、構成の読者進行を実現できたことは別。実モデル内部の見出し選択理由は特定できないので「場当たり的に生成している」こと自体を実証とはしない。
- 本文の_extra_instructionsは目的がawarenessでも一律CTA/CV導線を要求し、_build_cta_promptの専用配置工程とも食い違う。分量調整も潜在ニーズの章を最初に増減させ、共通の必須回答優先と違う。今回この既存2指示を置換し、構成の役割/説明順序と専用CTA配置、必須回答を保持して重複/補足から調整する既存方針へ統一。

### 残る設計の具体化案（未実装・未検証）

新しい調査/モデル確認工程や大きな読者心理シートを追加せず、既存の構成指示書を記事全体の進行設計にする。

1. 構成の既存リード設計・編集メモで、主検索意図に対する到達点と設定された記事目的とのつながりを短く決める。推薦が主意図でない記事を推薦導入にしない。
2. 各H2の既存「読者の疑問」を、その位置までに理解した内容と、まだ解消していない疑問・不安に基づいて定める。各H2の「回答要素」には新たに理解できる内容/判断できることを具体的に指定する。説明順序の根拠となる理解の進行が分かる短い指示書とし、同じ事実や感情文を別欄へ複製しない。
3. 既存のH2直下方針/子節の回答要素へ、結論→理由の具体化→必要な条件→その章で可能になる判断を割り当てる。すべての記事をこの固定順序へ押し込まず、その問いに必要な情報関係として設計する。
4. 次章はまだ残る疑問/次に必要な判断を担う。各章へ接続文を強制追加せず、順序と内容の役割でつなぐ。感情の変化は読者理解の仮説として、不安の解消に必要な情報と選択肢で支え、「安心した」「登録したくなった」と断定しない。CVなら理解・不安の整理後に商材選択/行動、認知なら理解・記憶、情報目的なら問いの解消を到達点にする。
5. 本文の既存役割指示で構成の上記設計を実際の説明・例・条件・自然な接続に実現し、内部ラベルは本文へ転記しない。共感は既存の配置方針に従い、各章の導入へ強制増殖しない。
6. 既存coverage/consistencyで、実際に理解・判断が進む説明があるか、まだ説明していない知識を前提にしていないか、関連情報やCTAの存在だけで主回答を代替していないかを評価する。心理状態の変化そのものを推測で合格としない。

今回の「やばい」の候補進行: リスクの理由と生活への影響を理解→法的境界/具体的な対策を判断→使う場合の選び方を理解→確認済みの商材比較と選択。理由3H3から対策等への役割移動で重複を減らす。各段階の適切さは生成した全構成で評価し、流れの文言だけで合格にしない。

### 検証方針

実際の通常構成の要求・引継ぎを無料で検査した後、既存の有料構成生成と確認で評価する。リスク情報/比較推薦/手順の異なる意図に対して、主回答の詳述・説明順序・目的に適した到達点が実現されるかを確かめる。各章の欄が埋まることやH3の数だけで合格にしない。読者状態の過剰な記録・事実の複製で構成出力が膨らまないことも評価する。通常構成生成から本文までの引継ぎ未検証であれば完了扱いにしない。
